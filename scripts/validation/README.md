# Foundation public boundary

- `npm run validate:source` checks the intended public checkout before dependency installation in CI. `npm run validate:dist` checks the built entry point, the case-sensitive project prefix and the limited foundation artifact inventory.
- Start with only `index.html`, Vite's JavaScript/CSS/first-party SVG assets, and optionally an app-owned `favicon.svg` or `exam-icon.svg`. Expand the artifact allowlist only after reviewing the feature and its content policy. Keep source maps off in public builds.
- The checks are defense in depth, not proof that arbitrary content is rights-cleared or secret-free. They reject known private paths, credential/PDF markers, bulk copies, symlinks, unrelated output and broken resource paths. Findings print rule categories and counts, not sensitive samples or paths. Review all intended tracked paths and their contents before any public push. Never put private source material or the owner-approved private fixture into this checkout, dependency caches, or generated output.
- Phase 3 public CI runs `npm run test:bank` before the build, with synthetic fixtures only. This exercises failure gates; it does not perform real source-answer comparison or semantic review. Run those privately with pinned authorized inputs and separate release approval. Keep extracted records, private reports, PDFs, and Python bytecode outside the public checkout. No real bank is published by this workflow. Client-side scoring cannot make scoring data secret.
- Workflow actions are pinned to reviewed release commits. Review an official release and verify its full commit SHA before any update. CI does not install a deploy job or upload artifacts.
- Phase 5 keeps the real-content candidate runner separate from the public Vite entry. After the ordinary build, `node scripts/validation/verify-public-graph.mjs` verifies that the public HTML and boot module are used and that no private runner, local display virtual module, or private bank adapter appears in the build graph. The in-memory build must reproduce every emitted file in the existing `dist`, and unverified JavaScript files fail the check. CI leaves private input and screenshot destinations unset. Keep any locally authorized private candidate build and visual evidence outside this checkout and never add a Vite public-entry flag to select private content.
- **Phase 5 manual screen reader: NOT PERFORMED.** The available Linux workspace did not have an interactive desktop screen-reader/browser combination, and no connected Windows or macOS environment was available. Chromium accessibility-tree, keyboard, and automated accessibility checks are separate evidence, not a substitute for a manual screen-reader run.
- Release CI validates synthetic content only. The protected full-bank runner, its local scoring module, private manifests, and review/evidence artifacts are not public source or output. The graph and artifact checks reject their named entry points and retained markers; do not weaken the guards to ship restricted material. The release branch trigger is validation-only. Merging the release PR neither enables Pages nor authorizes deployment.

References: [GitHub Actions workflow security](https://docs.github.com/en/actions/reference/security/secure-use), [Vite static deployment](https://vite.dev/guide/static-deploy#github-pages), [Playwright CI](https://playwright.dev/docs/ci).
